Overview

A full-stack application from the Advanced Java course. It demonstrates layered architecture: the separation of presentation, business logic and data access, built with a Spring Boot backend connected to a relational database and an Angular frontend that consumes REST endpoints.

Architecture

Three layers, each with a single responsibility.

  1. Presentation layer: Angular, TypeScript and the HTTP client
  2. Business logic layer: Spring Boot, REST controllers and service classes
  3. Data access layer: JDBC, SQL and the repository pattern

Backend

The backend exposes REST endpoints. Business logic lives in service classes, which keeps the controllers thin and the data access layer isolated. Database access uses JDBC with plain SQL and parameterized queries, with no ORM. That made the data layer transparent and showed me which queries actually ran.

  • Spring Boot for dependency injection and the REST controllers
  • CRUD endpoints, tested and documented with Postman
  • Parameterized queries to prevent SQL injection
  • Relational schema design and data modeling in SQL

Frontend

The Angular frontend calls the backend through Angular's HTTP client. Components are organized around the data model, and services handle the API calls.

What I learned

  • Why layered architecture matters: changing the database layer did not require touching the business logic, and the other way around
  • How dependency injection works in Spring Boot in practice, not only in theory
  • The full REST request and response cycle: routing, serialization, error handling and status codes
  • How to test an API with Postman before building the frontend
  • The tradeoff between JDBC and an ORM: raw SQL is clearer but more verbose
